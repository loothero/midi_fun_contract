# Replace the original 75 Beasts' Sound Checks with distinct original-lab-inspired warmups

**Status: proposed implementation plan, no composer or contract changes.** Source/data analysis is complete; the musical proposals need listening in the actual player. All work is isolated in `/tmp/beast-sound-scale-plan/`. Exact source snapshots and findings are in [source-audit.md](source-audit.md); the supervised pairing agent's 75 recommendations are in [pairings.csv](pairings.csv), [pairings.json](pairings.json) and [pairing-rationale.md](pairing-rationale.md).

The user's latest preferences control the plan:

- Beasts must have different musical identities. A single ascending/descending pattern transposed 75 ways is insufficient.
- The user's own original sampler, particularly its variety and #406's pacing/motif/stereo movement, is the reference.
- **Cyclops64: the WHOLE original #504 sequence, all eight sounds, is the preferred mainnet Sound Check.** This overrides a generic Brute preset recommendation. Its eight client-bank programs and token-effects behavior require explicit qualification.
- **Satori44: original #411 is the preferred Species Song, also the intended base for Agony Bane Satori.** This is a separate song-authoring change, not permission to treat that 72-second song as a generic short Sound Check. Its [feasibility review](satori-411/ASSESSMENT.md) documents the exact rendering and name-treatment choices. The prior G harmonic minor song is current evidence, not a contrary final recommendation.

## Recommended musical result

For the remaining general catalogue, use the original demos' clear single-instrument voice, held-note character, short articulation and varied pace, with short phrases that suggest each Beast. Curate each species' preset, contour, rhythm, cadence, register, tempo and optional stereo response. A finite table of75 compact records and ten reusable phrase families is enough; avoid another procedural song engine.

Use the **written, published Species Song's actual mode and pitch class** as the normal note palette. All75 modes/tonics in the legacy lab were checked against V3's committed Song recipes and match. Scale IDs4/5/6/7/8/26 mean Dorian/Phrygian/Locrian/Aeolian/harmonic minor/Dorian#4; preserve their actual interval tables. Harpy39/Pegasus40 take their swapped song's key. Satori is an explicit future exception if #411 replaces its song; adapt its eventual warmup to the chosen #411 A-minor palette rather than the superseded G harmonic minor.

Register can move by whole octaves for a comfortable solo voice. Most proposed leads use a tonic in60–71; darker plucks use48–59; the Yeti proposal uses an octave-call contour in a comfortable solo register. The verified proposal bounds are in the pairing artifact. This is a deliberate listening choice: same pitch-class palette does not mean every check must use the song's bass-register tonic. Do not import the absolute C-major scale or #406's literal G/A/B/C# whole-step fragment into every modal song.

The general proposal uses all18 nonmega essentials within their current families, with50/65 as token-effects variants. These assignments are aesthetic judgments informed by oscillator/envelope/vibrato facts and the current songs. The existing family sound banks already supply them, so the general route needs no larger bank. A short check may use a pluck when the song's leading line uses a sustained lead; sharing the exact topline timbre would remove much of the variety the user likes. Both the verified theme voice and the legacy-rendered highest voice are recorded so this tradeoff is reviewable. The highest voice is not reliably given by `species%3`.

The pairing table proposes ten contour families: incantation, spiral, veil, spring, flight, hunt, skitter, stomp, surge and yodel, four cadence choices and six rhythm grids. It contains explicit head/response degree arrays rather than relying on a hash as the musical review. Some responses quote the species' written theme; some descend or answer it. Selected phrases leave a final rest, drawing on #406's breathing space. The default is a32-beat loop, approximately11–21seconds across the original7-tempo palette; #504 and #411 retain their own structure when exact references are requested. The table is a concrete audition starting point, not proof that these are optimal to the ear.

It is **eight presets**, not a single program whose name happens to be “Arp/FX”. The source text says these were client-bank demonstrations outside the20 onchain essentials.

The user explicitly selected the whole eight-sound sequence; do not narrow this to one favorite preset. No new waveform implementation is required. Do not substitute a Brute preset while calling it #504. Prefer the small existing settings/generator extension if supported. If any operator needs engine work, expose the audible mismatch in the preview and keep the full reference as the comparison.

Preserve the actual preferred base while deciding token-effects behavior. The original track's shiny artwork does not apply the production mega sound. V3 Genesis tokens have sound_effects1, whose current generic check path normally changes tempo and replaces the instrument with50/65. An unexamined reuse of that path would change the user's chosen reference immediately. Recommended audition order: exact #504 in current TinySynth first; then the existing0–3 effects behavior as explicitly labeled variants. For mainnet, keep the reference's defining eight timbres and program changes; apply only approved tempo/articulation changes. Do not drop the eight-program identity under a mega substitution. ### Satori: original #411

Original #411 is “Long track: loop and seam ·120BPM”:36bars/72seconds, Am–F–C–G, bass, harp, lead, drums and an arranged break. The user has selected it as a **Species Song replacement** and wants Agony Bane Satori to use it as its base. Do not smuggle #411 into a scale preset or claim that changing the shared selection changes the generator's named base.

## Publication and mainnet handoff

V3's current shared-track fixture contains75 **Species Songs**, not75 Sound Checks. Changing `sound_check.cairo` changes check composition when that path is invoked; it does not automatically replace those published songs or select checks on every token.

Create a reviewed75-check publication fixture from the approved Song palettes and musical records, separate from the existing75 Song fixture. On a fresh manager, publish/select the checks for the intended launch phase, then append songs later without renumbering references. On an existing manager, append new checks and deliberately update species selection/defaults; never try to overwrite immutable shared inputs. Track selection and per-track modes are separate, and holder overrides may retain another choice. Capture actual inherited/overridden behavior during release rehearsal.

Before any mainnet action, inspect the actual deployment's manager route, configuration authority/freeze state, catalogue and intended default selection. If authority remains, a composer retarget can affect every track using it and needs the noncheck parity evidence above. If frozen, the current manager cannot be patched in place; use the established reviewed replacement/route procedure only while the registry route permits it. The existing `deploy-sound.mjs` is Sepolia-only and explicitly installs Songs; do not present it as a ready mainnet check migration command. A concrete dry-run/publication review belongs to the later implementation task.

This plan introduces no new hot-path RPC, trusted service or authorization check. Curated notes, existing input validation and existing contract checks are sufficient. Questions remaining for musical approval are limited to what is audible: exact vs adjusted selected-reference performance, Satori's named treatment, final phrase/preset edits and optional stereo/rest choices. Those are carried as visible review items; no new approval bureaucracy is needed for ordinary implementation.
